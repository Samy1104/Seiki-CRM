## Design Specificity Verdict

**LLM assessment:** The Portal entry screen is genuinely authored for Seiki — the Playfair Display split-panel at 9rem, noise texture overlay at 0.03 opacity, coordinated flex animation, and choreographed staggered reveals are not template SaaS. But the moment users enter the CRM, brand identity retreats to palette depth only: a dark left-sidebar with icons, tabbed content, data tables, kanban. The charcoal-amber token system is applied consistently, but the compositional logic is interchangeable with any dark-theme admin dashboard. The distinction from a reskinned Pipedrive is primarily color-token-deep, not architectural. Two different design ambitions live in the same product.

**Deterministic scan:** 7 warnings, all in the "slop" category — no errors, no quality or accessibility detector findings. Affected files: `src/views/Login.tsx` (Inter font, 2 hits), `src/views/Portal.tsx` (bounce/elastic easing cubic-bezier(0.34, 1.56, 0.64, 1), 2 hits), `src/views/tasks/TaskListView.tsx` (side-tab accent border, 1 hit), `src/components/stats/StatsPipelineTab.tsx` (side-tab border-l-4, 1 hit), `src/components/ui/KpiTile.tsx` (border accent on rounded element, 1 hit). The bounce easing in Portal.tsx is a possible false positive — it applies a spring-like overshoot to the title translateY on hover, which could be intentional theatrical flourish. All other findings are confirmed.

## Overall Impression

The Portal is the best thing in this product: a rare example of an internal tool that opens with genuine editorial ambition. Everything downstream of it is competent but unexpressive — functional dark-theme SaaS. The single biggest opportunity is closing the gap between the Portal's authorial confidence and the CRM interior's generic adequacy. The two most urgent fixes before anything aesthetic: the global focus ring destruction (P0 accessibility blocker) and the window.confirm() pattern that breaks every destructive action flow with a browser-native popup.

---

## What's Working

1. **Portal entry screen is category-distinguishing.** The animated flex split-panel, Playfair Display at clamp(4rem, 10vw, 9rem), noise texture overlay at 0.03 opacity, and staggered element reveals create a premium first impression that no CRM template produces. This is a genuine authorial decision.

2. **Semantic token architecture is well-considered.** The surface/elevated/hover surface ramp, line/line-strong/line-focus border ramp, and ink/ink-soft/ink-faint text ramp in theme.css give components a coherent visual grammar that would scale cleanly — when followed consistently.

3. **Pipeline move optimistic UI with rollback is correct.** Lead state updates immediately in the UI, the network request runs async, and on error the board reverts to server truth. The animated KpiTile count-up with prefers-reduced-motion respect shows attention to detail beyond the obvious.

## Priority Issues

### [P0] Global focus ring destruction breaks keyboard accessibility
**Why it matters:** `index.css` applies `outline: none !important` and `box-shadow: none !important` to every element including `*:focus-visible`. This removes the browser's only built-in keyboard navigation indicator across the entire application. Keyboard-only users cannot determine which element is focused at any time. This violates WCAG 2.1 SC 2.4.7 (Level AA) and makes the product practically unusable without a mouse.
**Fix:** Remove the blanket `*:focus, *:focus-visible` outline removal. Add a global `:focus-visible` rule using the brand focus token: `outline: 2px solid rgba(212, 196, 168, 0.35); outline-offset: 2px` (the existing `--color-line-focus` value). Apply targeted resets only to elements with custom focus states.
**Suggested command:** `/impeccable audit src/` to find all accessibility violations systematically.

### [P0] window.confirm() used for all destructive actions
**Why it matters:** Every delete, merge, and archive confirmation calls `window.confirm()`, which renders a bright browser-native dialog that ignores the dark theme entirely, blocks the JavaScript event loop, and feels like a bug inside a premium UI. A `ConfirmDeleteModal` component already exists in `src/components/ConfirmDeleteModal.tsx` and is used only in Agenda — it's never been wired to the other views.
**Fix:** Replace all `confirmAction()` calls with `ConfirmDeleteModal`, adding a consequence description to each ("Vous perdrez aussi X tâches et Y notes liées à ce lead.").
**Suggested command:** `/impeccable harden src/` to standardize all destructive action flows.

### [P1] Login headline is in English
**Why it matters:** `src/views/Login.tsx` displays "Sharper decisions with mobility data" — English copy inside a product that is otherwise entirely in French, specified as French-only in the brand constraints. This is the first screen authenticated users see before reaching the Portal. It reads as unfinished.
**Fix:** Replace with French copy appropriate to the CRM purpose. Candidate: "Votre pipeline commercial, en un coup d'œil." Or use an actual Seiki brand statement if one exists.
**Suggested command:** `/impeccable clarify src/views/Login.tsx`

### [P1] No keyboard shortcuts or command palette
**Why it matters:** Users who work in the CRM daily have no path to efficiency beyond point-and-click. No shortcut to create a new lead, jump to Pipeline, search across leads, or trigger a task. The power user is stuck in full click-through navigation for every action on a tool they use multiple times per day.
**Fix:** Add a minimal keyboard shortcut layer at the layout level: `N` for new entity depending on current view, `/` or `Cmd+K` for a global search/command palette, `G+P/G+L/G+T` for module navigation. A single `useKeyboardShortcuts` hook registered at CrmLayout covers all cases.
**Suggested command:** `/impeccable shape keyboard shortcuts` before implementation.

### [P1] Agenda form opens by default on every visit
**Why it matters:** `formOpen` is initialized to `true` in Agenda.tsx. Every time a user navigates to Agenda, they are forced to scroll past an open creation form before seeing their events. The consultant checking their schedule between meetings sees the form before seeing any events — the opposite of progressive disclosure.
**Fix:** Initialize `formOpen` to `false`. Add a prominent "Ajouter un événement" button. Optionally persist the preference in localStorage.
**Suggested command:** `/impeccable distill src/views/Agenda.tsx`

### [P2] Side-tab accent borders are AI-generated UI signatures
**Why it matters:** The detector found `borderLeft: 3px solid` in `TaskListView.tsx:212` and `border-l-4` in `StatsPipelineTab.tsx:72` — both are the most recognizable AI-generated UI tell pattern. The DealCard left-border status coding in Pipeline is more defensible (4 status colors × position = explicit information encoding), but the Task and Stats usages have weaker information justification and read as decoration.
**Fix:** Replace the task left-border with a status indicator dot or badge. Replace the stats pipeline left-border with a full-height colored background at reduced opacity (e.g. `bg-[color]/10` on the row). The DealCard pattern can stay.
**Suggested command:** `/impeccable quieter src/views/tasks/TaskListView.tsx src/components/stats/StatsPipelineTab.tsx`

### [P2] Hardcoded hex values in Stats and Settings tabs bypass tokens
**Why it matters:** Stats.tsx uses `bg-[#141414] text-[#D4C4A8] border-t-[#D4C4A8]` for active tab state; Settings.tsx uses `bg-[#D4C4A8]/15`. When theme values change, these views will drift. The semantic equivalents (`bg-elevated`, `text-beige`, `border-beige`) already exist as Tailwind tokens.
**Fix:** Replace all hardcoded hex arbitrary values in tab active states with semantic token classes.
**Suggested command:** `/impeccable polish src/views/Stats.tsx src/views/Settings.tsx`

## Persona Red Flags

**Alex (Power User):** Zero keyboard shortcuts — no shortcut to create a lead, navigate between modules, or search globally. No bulk actions in the leads table (cannot batch-move, batch-archive, or batch-assign). Filter state resets on every navigation. The entire product offers one power-user affordance (Tasks column resizing) against eight daily use cases. Alex would start using a different tab to manage leads within a week.

**Sam (Accessibility-Dependent):** The global `outline: none !important` in `index.css` makes the product navigable by mouse only — keyboard focus is invisible on every element. The collapsed sidebar uses only `title` attributes for icon identification, which screen readers don't surface reliably. Pipeline and Tasks drag-and-drop have no keyboard alternative. Score colors (green/amber/red on deal cards) are used as the sole status indicator with no text alternative.

**Riley (Stress Tester):** Moving a card to the "Perdu" column silently auto-archives it with only a toast — Riley discovers this by accident with no warning and no undo. Empty pipeline with no stages configured renders a blank kanban area with no prompt. The merge proposal flow triggers on a single `window.confirm()` click with no preview of what "merged" means for the surviving record. No retry UI after failed data loads.

**Consultant-in-a-Hurry (project-specific):** The Portal is a mandatory intermediate stop on every session — there is no "remember my last module" behavior, adding a required click before every work session. The CODIR dashboard is at position 6/6 in the sidebar — the busiest summary view is the hardest to reach. No global search — finding a specific company requires navigating to Leads, waiting for load, then searching. The Portal animation (0.6s flex transition) adds latency on every entry for a team that clicks CRM 20+ times per day.

## Minor Observations

- The `--purple` alias in `index.css` maps to amber `#F59E0B` — a leftover from a previous purple design phase. Misleading naming for future contributors.
- The Codir print header references `fontFamily: 'Outfit'` — Outfit is not loaded anywhere. The print view falls back to system-ui.
- After login, users always route to `/portal` — no session context preservation regardless of where they were before.
- The Modal close button uses a plain `✕` text character rather than the Lucide `X` icon used throughout the rest of the product.
- `SegmentedToggle` exists and is used only in Leads.tsx; it could replace several other tab patterns (Stats, Settings, Tasks view mode) for visual consistency.
- `LeadDetailModal` is passed `teamMembers={[]}` from Leads.tsx — the assignee picker silently receives an empty array even if team members exist, making reassignment impossible from the lead detail view.
- The bounce-easing finder flagged `cubic-bezier(0.34, 1.56, 0.64, 1)` in Portal.tsx — this is likely intentional theatrical spring physics on the title reveal. Consider keeping it if it reads as intentional, or replace with a clean exponential ease-out if not.

## Questions to Consider

- Is the Portal split-screen the right permanent home for returning users, or should the app remember the last module and route there directly? The brand moment is strong for a first impression, but it imposes mandatory friction on every session for a daily-use tool.
- The CODIR dashboard is designed for boardroom presentation (fullscreen toggle, print support, confidential header) but lives as item 6/6 in a sidebar meant for daily navigation. Should it be a separate, elevated entry point — perhaps a third panel at the Portal level — that signals its distinct purpose?
- Every auto-behavior (Perdu auto-archive) and scoring threshold (80 = hot, 60 = qualified) is hardcoded and invisible to users. Should the tool make its own business rules surfaced and configurable in Settings, or does the team's shared context make opacity acceptable?
